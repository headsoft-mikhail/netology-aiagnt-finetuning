# Fine-tuning Qwen2.5-0.5B-Instruct с LoRA

Учебный проект адаптирует локальную instruct-модель для коротких русскоязычных
ответов службы поддержки интернет-магазина. Pipeline проверяет данные, сохраняет
ответы базовой модели, обучает LoRA adapter, повторно загружает его и сравнивает
ответы до и после обучения.

## Модель и метод

Базовая модель — `Qwen/Qwen2.5-0.5B-Instruct`, revision
`7ae557604adf67be50417f59c2c2f167def9a775`. Это causal instruct-модель примерно
на 0,49 млрд параметров. Она выбрана для учебного запуска, потому что понимает
русский язык и формат диалога, распространяется открыто, помещается в 16 GiB
unified memory и позволяет выполнить LoRA fine-tuning локально на Mac без
облачной GPU.

Выбрана LoRA. Модель помещается в 16 GiB unified memory в `float32`, а обучение
работает через MPS без 4-bit backend. Поэтому QLoRA для этого запуска не нужна.
Основные веса модели заморожены, обучаются адаптеры модулей `q_proj` и `v_proj`:

- `r: 8`;
- `lora_alpha: 16`;
- `lora_dropout: 0.05`;
- `bias: none`.

Ограничение модели — небольшой размер: уже до обучения она иногда плохо следует
system prompt и придумывает отсутствующие правила магазина.

## Окружение

Проверенный запуск:

- macOS arm64, 16 GiB unified memory;
- Python 3.12.14;
- PyTorch 2.14.0;
- Transformers 5.17.0;
- PEFT 0.21.0;
- устройство MPS;
- dtype `float32`.

Зависимости перечислены в `pyproject.toml`, конкретные версии записаны в
`uv.lock`.

## Установка

Все команды выполняются из корня репозитория:

```bash
just setup
just python 3.12.14
just lock
just install
just lint
```

Базовая модель публичная и не требует Hugging Face token. Она скачивается один
раз:

```bash
just download_model
```

Модель должна находиться в
`data/models/base/Qwen2.5-0.5B-Instruct/`. Каталог с базовой моделью исключён из
Git, потому что он восстанавливается командой выше и занимает около 1 ГБ.

## Данные

- `data/fine_tuning/train.jsonl` — 32 обучающих примера.
- `data/fine_tuning/eval.jsonl` — 5 отдельных проверочных примеров.

Каждая строка содержит уникальный `id` и список сообщений с ролями `system`,
`user`, `assistant`. Train и eval посвящены одной задаче, но имеют разные ID и
формулировки.

Перед обучением проверяются:

- наличие файлов и корректность JSONL;
- непустые уникальные ID;
- роли и содержимое сообщений;
- наличие запроса `user` и целевого ответа `assistant`;
- пересечение train и eval по ID;
- дубликаты диалогов;
- признаки секретов, электронной почты и телефонных номеров;
- ограничение `max_seq_length`.

Фиктивный номер `8-800-000-00-00` из учебного набора разрешён явно. Проверить
данные отдельно:

```bash
just validate_data
```

## Конфигурация

Пути, модель, параметры LoRA, обучения и генерации находятся в
`config/fine_tuning.yaml`. Для выполненного запуска использовались:

- seed `42`;
- learning rate `0.0002`;
- train/eval batch size `1`;
- gradient accumulation `4`;
- две эпохи;
- evaluation и checkpoint после каждой эпохи;
- хранение одного последнего checkpoint;
- `max_seq_length: 512`;
- детерминированная генерация с `max_new_tokens: 128`.

Prompt-токены `system` и `user`, а также padding получают label `-100`. Loss
рассчитывается по токенам целевого ответа `assistant`.

## Запуск

Проверка окружения:

```bash
just inspect_env
just inspect_env cpu
just inspect_env gpu
```

Команда проверяет версии Python и библиотек, наличие файлов базовой модели и
доступные устройства вычисления. Без аргумента устройство выбирается
автоматически; `cpu` принудительно использует процессор, а `gpu` требует
доступный ускоритель. Эта проверка нужна, чтобы обнаружить проблему с окружением
до загрузки модели и начала длительного обучения.

Полный цикл:

```bash
just fine_tune
```

Эта команда выполняет проверку окружения, baseline, обучение, сохранение
checkpoint и adapter, повторную загрузку adapter, tuned evaluation и сравнение.

Этапы можно запустить отдельно:

```bash
just train
just evaluate
```

`just train` запускает основной этап проекта из `fine_tuning/train.py`. Скрипт
загружает локальную модель и tokenizer, проверяет train/eval, преобразует
диалоги в токены и сначала измеряет loss и сохраняет ответы базовой модели.
Затем он подключает LoRA к модулям `q_proj` и `v_proj`, замораживает основные
веса, обучает только параметры адаптера и сохраняет checkpoint, итоговый adapter
и отчёт с метриками. При расчёте loss учитываются только токены ответа
`assistant`; system prompt, пользовательский запрос и padding исключаются.

`just evaluate` загружает adapter из
`data/models/adapters/lora-tuned-Qwen2.5-0.5B-Instruct/`, применяет ручные оценки
из `data/fine_tuning/manual_evaluation.json` и создаёт итоговое сравнение с
базовой моделью.

## Сохранённые результаты

Trainer выполнил 16 шагов оптимизации: 32 train-примера × 2 эпохи ÷ gradient
accumulation 4 = 16. Поэтому автоматически созданный checkpoint называется
`checkpoint-16`.

- Checkpoint:
  `data/fine_tuning/runs/lora-tuned-Qwen2.5-0.5B-Instruct/checkpoint-16/`.
- Итоговый adapter:
  `data/models/adapters/lora-tuned-Qwen2.5-0.5B-Instruct/`.
- Baseline: `data/fine_tuning/reports/baseline_report.json`.
- Метрики обучения: `data/fine_tuning/reports/training_report.json`.
- Оценка adapter: `data/fine_tuning/reports/tuned_report.json`.
- Сравнение: `data/fine_tuning/reports/comparison_report.json`.

## Результаты эксперимента

| Метрика | Baseline | После LoRA |
| --- | ---: | ---: |
| Eval loss | 1,7137 | 1,4528 |
| Perplexity | 5,5495 | 4,2752 |
| Ответы, прошедшие ручную проверку | 0 из 5 | 0 из 5 |
| Pass rate | 0% | 0% |

Средний train loss — `1,3421`. Вторая эпоха завершилась с меньшим eval loss,
чем первая (`1,4528` против `1,5220`), поэтому по этому короткому запуску явного
роста eval loss нет. По ручной оценке все пять сравнений получили статус
`unchanged_fail`: улучшений `0`, регрессий `0`, неизменившихся результатов `5`.

## Почему качество ответов не улучшилось

Снижение loss означает, что модель стала точнее предсказывать токены эталонных
ответов при teacher forcing. Это не привело к прохождению прикладных критериев во
время свободной генерации.

Основные причины:

1. В train только 32 примера, причём многие являются близкими перефразировками.
2. За две эпохи выполнено всего 16 шагов оптимизации, а LoRA изменяет только
   небольшую долю параметров в `q_proj` и `v_proj`.
3. Базовая модель 0.5B уже до обучения слабо следовала некоторым инструкциям.
4. Eval состоит из пяти примеров. Строгая бинарная оценка не учитывает частичные
   улучшения, если ответ всё равно содержит ошибку.
5. Запуск ограничен доступным оборудованием: Mac с 16 GiB unified memory и MPS,
   поэтому более крупные модели в этом эксперименте не проверялись.
6. Ручная оценка выполнена в рамках учебной работы и не заменяет полноценную
   экспертную оценку на большом наборе запросов.

Eval loss снижался на обеих эпохах, поэтому явных признаков переобучения в этом
запуске нет. Однако пять eval-примеров слишком мало, чтобы надёжно исключить
переобучение.

Например, для `eval_003` модель после обучения перестала отказываться от ответа,
но придумала отправку письма вместо требуемой отправки фото в чат поддержки.
Поэтому ответ остался не прошедшим проверку.

Следующая итерация должна добавить более разнообразные примеры по пяти
проваленным темам, расширить eval, проверить больше эпох с выбором checkpoint по
eval loss и при необходимости использовать модель 1–1.5B.
